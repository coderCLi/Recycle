# PRD: 富区旧家电回收

*基于产品简报（brief-airecycle-20260701）和PRFAQ（prfaq-airecycle.md）。*

## 0. Document Purpose

本PRD面向开发实施和运营团队。文档结构：Glossary定义领域术语 → Vision明确方向 → User Journeys描述真实场景 → Features按用户端/后管/回收员端分组，每项功能嵌套可测试的FR。`[ASSUMPTION]`标签标注了待确认的推断。

## 1. Vision

富区旧家电回收小程序将富拉尔基现有线下回收业务（日均20单/3-4人/全县独家）数字化。核心变化：从"用户扛东西来门店"变成"用户拍照→AI估价→预约上门→当面成交"。

这是一次防守反击——目前在富拉尔基没有竞争对手，但互联网回收平台（绿巨能等）正在下沉。小程序是用最低成本（¥50-100/月）守住全县唯一地位并建立数字化壁垒的方式。

## 2. Target User

### 2.1 Jobs To Be Done

**C端用户：**
- 不想扛重物出门 → 想知道旧东西值多少钱 → 能预约人上门来收
- 装修/搬家时有一堆东西要处理 → 批量估价、一次性清空
- 帮家里老人处理旧家电 → 远程代操作

**内部运营（磊哥 + 回收员）：**
- 从"接电话→记单→分配→对账"变成"系统自动流转"
- 回收员手机接单、导航、签收、看业绩
- 管理者看数据、调价格、管人

### 2.2 Non-Users (v1)

- 不面向富拉尔基以外的用户
- 不支持企业/工厂级别的批量工业废料回收
- 不支持C2C二手交易（不跟闲鱼竞争）

### 2.3 Key User Journeys

**UJ-1. 王姐卖旧洗衣机**
40岁家庭主妇，阳台堆了两年旧洗衣机。在小区群里看到小程序二维码 → 打开拍照 → 10秒后看到估价¥100-150 → 选明天上午9:00-9:30 → 第二天回收员老李准时到 → 当面确认¥120 → 微信到账 → 系统自动发"减碳报告"可分享朋友圈。

**UJ-2. 小张帮爸妈处理旧家电**
25岁在外地上班，过年回富拉尔基发现父母攒了一屋子旧电器。小程序拍照批量估价 → 5件总计¥680 → 选同一天下午统一上门 → 回收员上门一次性清空 → 父母不用搬任何东西。

**UJ-3. 老李（回收员）接单**
回收员老李早上打开回收员端 → 看到今天分配了6单 → 按地图导航顺序出发 → 每单前10分钟系统自动通知用户 → 到现场确认价格 → 用户满意签名 → 微信支付到账 → 老李点"完成" → 系统自动算业绩积分。

**UJ-4. 磊哥看后管**
晚上打开后管数据大屏 → 今天线上12单+线下8单=20单 → 比上周日均+3单 → 品类分布：冰箱最多 → 估价偏差率5.2%→ 回收员老李积分最高 → 有个用户拍照估价了但没下单，点一下"发送提醒"。

## 3. Glossary

- **估价** — AI对物品给出的预估价格区间（非最终成交价），用户下单前可见
- **最终价** — 回收员上门后现场确认的实际成交价格
- **品类** — 回收物品的一级分类：家电/电脑/手机/废纸/废金属/塑料/其他
- **成色** — 物品状况等级：全新/良好/一般/损坏
- **回收员** — 执行上门回收的员工，每人有独立账号和工作区域
- **线上单** — 通过小程序下单的回收订单
- **线下单** — 未通过小程序、直接在门店或电话成交的订单，后管手动录入
- **时间窗** — 用户预约的30分钟上門时段
- **估价偏差** — 预估报价与最终成交价之间的百分比差异
- **积分** — 回收员考核分数，由单量+满意度+响应速度+准时率加权计算

## 4. Features

### 4.1 小程序 — 拍照估价

**Description:** 用户进入小程序后，核心操作是拍照获取估价。打开相机或从相册选取照片，调用百度AI识别品类和品牌，结合本地价格表给出预估回收价区间。实现UJ-1、UJ-2。

**Functional Requirements:**

#### FR-1: 拍照识别物品
用户可从相机拍摄或从相册选取物品照片。系统调用百度AI通用物体识别API，返回品类和品牌名称。`[ASSUMPTION: 百度AI对废旧家电（冰箱/洗衣机/空调/电视/电脑）的识别准确率>80%，需上线后验证]`

**Consequences (testable):**
- 上传照片后3秒内返回识别结果
- 识别失败时提示"未能识别，请换个角度再拍一张"而非报错
- 支持多张照片批量上传（最多5张）

#### FR-2: 生成预估报价
系统根据识别结果+本地价格表+默认成色系数，生成估价区间（如"¥100-150"）。

**Consequences (testable):**
- 估价在识别完成后1秒内展示
- 估价区间下限 ≥ 0，上限 ≤ 品类最高限价
- 估价页面显示"最终价格以回收员上门确认为准"

**Out of Scope:**
- v1不包含成色AI自动评估（固定使用"一般"档位）
- v1不包含实时大宗商品价格联动

#### FR-3: 价格表后管可配置
所有品类的基准价格、折旧系数、成色系数在后管可修改。

---

### 4.2 小程序 — 预约上门

**Description:** 用户看到估价后，可选择时间段预约上门回收。无需注册，用微信手机号授权即可。实现UJ-1。

**Functional Requirements:**

#### FR-4: 选择时间窗
用户选择日期和30分钟时间窗（如"明天9:00-9:30"）。

**Consequences:**
- 可预约未来3天内的时间窗
- 已被占用（已有2单以上）的时间窗灰色不可选
- 预约成功显示确认页：时间+地址+估价+回收员预计到达

#### FR-5: 免注册下单
用户首次下单仅需微信手机号授权，无需填写任何额外信息。

**Consequences:**
- 首次用户从拍照到下单完成 < 30秒
- 再次使用自动记住上次地址和时间偏好

#### FR-6: 订单状态追踪
用户可在"我的订单"查看订单状态：待确认→已派单→回收员已出发→服务中→已完成。

**Consequences:**
- 回收员出发后用户看到"回收员正在路上"和预计到达时间
- 订单完成时显示成交价和减碳数据

---

### 4.3 小程序 — 基础功能

#### FR-7: 微信搜一搜可达
小程序名称"富区旧家电回收"在微信搜一搜中可被搜索到。

#### FR-8: 订阅消息推送
用户授权后，系统在回收员出发前10分钟推送提醒。

**Consequences:**
- 推送到达率 ≥ 90%
- 用户可随时关闭订阅

#### FR-9: 分享裂变
完成订单后可生成"减碳报告"海报，分享到朋友圈或微信群。

**Consequences:**
- 海报包含：回收物品名称、减碳量、小程序码

---

### 4.4 后管 — 订单管理

**Description:** Web后管核心页面，管理线上线下全渠道订单。实现UJ-4。

**Functional Requirements:**

#### FR-10: 全渠道订单列表
展示所有订单，包含来源（线上/线下）、状态、用户、品类、金额、回收员、时间。支持搜索和筛选。

**Consequences:**
- 订单按时间倒序排列，默认显示今日
- 可按状态/回收员/品类/日期筛选
- 支持导出Excel

#### FR-11: 订单状态流转
管理员可手动变更订单状态：待派单 → 已派单 → 服务中 → 已完成 → 已取消。

**Consequences:**
- 状态变更记录操作人和时间
- 取消订单须填写原因

---

### 4.5 后管 — 线下数据录入

**Description:** 未通过小程序的线下回收单（门店/电话），由管理员或回收员手动录入后管。实现线上线下数据统一。

**Functional Requirements:**

#### FR-12: 手动录入回收单
录入字段：品类、重量/数量、金额、客户来源（门店/电话/熟人）、回收员、日期。

**Consequences:**
- 录入后自动纳入统计数据
- 支持批量导入（Excel模板）

---

### 4.6 后管 — 多端数据对比

**Description:** 线上vs线下回收数据的可视化对比分析。

**Functional Requirements:**

#### FR-13: 线上vs线下对比看板
按日/周/月/自定义时段，对比线上单量和金额vs线下。

**Consequences:**
- 默认为本月数据，折线图+柱状图
- 可按品类/回收员/区域下钻

---

### 4.7 后管 — 回收员管理

**Description:** 回收员的审核、分配、业绩排行和结算管理。实现UJ-3、UJ-4。

**Functional Requirements:**

#### FR-14: 回收员列表与状态
列表展示：姓名、电话、服务区域、状态（在岗/休息）、今日单量、总单量。

#### FR-15: 回收员积分排行
系统自动计算积分：单量(40%)+用户满意度(30%)+响应速度(15%)+准时率(15%)。

**Consequences:**
- 排行每日更新，支持历史排行查看
- 金牌/银牌/铜牌自动评定

#### FR-16: 结算管理
管理员可查看每个回收员的待结算金额和已结算记录。

**Consequences:**
- 结算金额 = 订单金额 × 回收员分成比例
- 支持按周/月批量结算

---

### 4.8 后管 — 品类定价配置

**Description:** 所有回收品类的价格参数管理。实现FR-3的后管支持。

**Functional Requirements:**

#### FR-17: 品类库管理
品类列表：名称、基准价格、单位（台/公斤/件）、折旧系数、是否启用。

**Consequences:**
- 支持新增/编辑/禁用品类
- 修改即时生效，不影响已完成的订单

#### FR-18: 估价偏差监控
展示每个品类的估价偏差率（预估vs实际成交）。

**Consequences:**
- 偏差率 = |预估价-成交价| / 预估价 × 100%
- 偏差率 > 20% 的品类标红提醒

---

### 4.9 后管 — 用户管理

**Description:** 小程序注册用户的管理和运营。

**Functional Requirements:**

#### FR-19: 用户列表
展示注册用户：头像、昵称、手机号、注册时间、订单数。

#### FR-20: 零单用户唤醒
筛选"估价过但从未下单"的用户列表，支持一键推送订阅消息。

**Consequences:**
- 推送内容模板可配置（如"您估价的XX，今日加价回收"）
- 记录每次推送的时间和转化结果

---

### 4.10 后管 — 竞品价格监控

**Description:** 手动录入竞品报价与aiRecycle对比。`[ASSUMPTION: v1手动录入，v2考虑自动爬取]`

**Functional Requirements:**

#### FR-21: 竞品报价录入
录入字段：竞品名称、品类、报价、日期。

**Consequences:**
- 自动展示aiRecycle同类报价对比
- 报价偏离 > 15% 时标黄提醒

---

### 4.11 回收员端 — 接单与导航

**Description:** 回收员通过小程序内的回收员入口（或独立小程序）查看分配给自己的订单、导航、签收。

**Functional Requirements:**

#### FR-22: 回收员订单列表
回收员查看今日分配给自己的订单，按时间排序。

**Consequences:**
- 每单显示：用户地址、品类、估价范围、时间窗
- 点击"出发"后自动通知用户

#### FR-23: 导航到用户地址
点击订单可唤起微信内置地图导航。

#### FR-24: 现场确认与签收
回收员填写：最终成交价、实际品类（如与预估不同）、备注。用户可当面确认（回收员手机展示确认页）。

**Consequences:**
- 成交价修改须注明原因
- 签收后自动触发微信支付到用户

---

### 4.12 平台基础能力

#### FR-25: 微信支付收款
小程序支持微信支付，用户在确认成交后收款。

#### FR-26: 数据导出
后管所有列表页支持导出Excel/CSV。

#### FR-27: 管理员鉴权
后管通过微信扫码登录，仅限预设管理员。

## 5. Non-Goals (Explicit)

- 不建C2C二手交易市场（不跟闲鱼/转转竞争）
- 不做全国扩张——v1仅服务富拉尔基
- 不做AI自动成色评估——v1使用固定系数
- 不做实时大宗商品价格联动报价
- 不接入第三方回收商/拆解厂API
- 不做APP——仅微信小程序+Web后管
- 不做语音/直播/视频客服
- 不接物联网智能回收箱硬件

## 6. MVP Scope

### 6.1 In Scope
- 小程序：拍照估价、预约上门、订单追踪、微信支付、分享裂变
- 后管：订单管理、线下录入、多端对比、回收员管理、品类定价
- 回收员端：订单列表、导航、签收

### 6.2 Out of Scope for MVP
- 估价偏差自动优化 → v2 `[NOTE FOR PM: 需要100+单数据积累]`
- 回收员积分排行与结算联动 → v2
- 零单用户唤醒 → v2
- 竞品价格监控 → v2
- 物品去向追踪 → v3
- 数据大屏 → v2
- 财务对账模块 → v2
- 独立回收员小程序 → v2（MVP在小程序内嵌回收员入口）

## 7. Success Metrics

**Primary**
- **SM-1**: 小程序日均下单量 ≥ 10 单（3个月内）。验证FR-2~FR-6。
- **SM-2**: 后管线上+线下总单量 ≥ 日均 30 单（6个月内）。验证FR-10~FR-13。

**Secondary**
- **SM-3**: 拍照→下单转化率 ≥ 40%。验证FR-1~FR-4。
- **SM-4**: 回收员周均积分差异 < 30%（系统分配公平性）。
- **SM-5**: 用户复购率 ≥ 30%（使用过2次以上）。验证FR-9。

**Counter-metrics**
- **SM-C1**: 不追求"拍照次数"——用户反复拍照但不下单，说明估价体验有问题，不是好事。
- **SM-C2**: 不追求"日均在线时长"——小程序是用来完成任务的，不是用来刷的。
