## 技术概览

### 问题定义

用户拍照 → 系统自动识别物品（品类/品牌/型号/成色） → 生成估价。核心技术链路：

```
拍照 → 物体检测 → 品类识别 → 品牌/型号识别 → 成色评估 → 价格估算
```

### 现有方案扫描

| 方案 | 特点 | 适用场景 |
|------|------|------|
| **再生博士 APP** | AI视觉+行业数据库，覆盖"识别-分析-估值"全流程，手机拍照即可 | 废料回收（金属/塑料/纸） |
| **ScrapScout** | AI扫描估价，49秒出结果，自动匹配买家，AI谈判助手 | 废品回收 |
| **爱回收 AI质检** | 38项质检标准，AI定价模型，微距镜头+传感器 | 3C/手机回收 |
| **Entrupy** | 微距镜头阵列+近红外光谱，奢侈品鉴真+估价，98%准确率 | 奢侈品 |
| **CHERRY AI** | 视觉识别+价格发现，拍照即获取二手准确定价 | 通用二手 |

_Source: 搜狐科技 2025.5、再生博士官网、CSDN_

## AI 识别技术分析

### 技术路线对比

| 路线 | 代表方案 | 优点 | 缺点 | aiRecycle 适配 |
|------|------|------|------|:---:|
| **API 调用（推荐起步）** | 百度AI / 腾讯云 / 阿里云 | 零部署、快速上线、成本可控 | 品类覆盖可能不够细、需调优 | ⭐⭐⭐⭐⭐ |

## 自动估价技术分析

### 估价模型架构

```
输入 → AI识别结果（品类+品牌+成色）
    → 二手市场数据（闲鱼/转转/爱回收历史成交价）
    → 拆解价值数据（废钢/废铜/废塑料大宗价格）
    → 本地化系数（城市/新旧/供需）

输出 → $ 零件级报价明细
```

### 数据源

| 数据维度 | 来源 | 获取难度 |
|------|------|:---:|
| 品牌型号库 | 公开数据库 + 爬取电商 | 🟡 中等 |
| 二手成交价 | 闲鱼/转转 API 或爬取 | 🔴 困难（反爬） |
| 大宗商品价 | 上海有色网/我的钢铁网 | 🟢 容易（有公开报价） |
| 成色-价格映射 | 需自建训练数据 | 🔴 困难 |
| 历史用户成交 | 自积累 | 🟢 时间积累 |

### 报价公式（MVP）

```
预估报价 = 残值基准 × 成色系数 × 折旧系数 × 本地系数

残值基准 = f(品牌, 型号, 品类)
成色系数 = AI识别（全新/良好/一般/损坏）
折旧系数 = 1 - (使用年限 / 预期寿命)
本地系数 = 富拉尔基地区供需调整
```

### 竞品估价准确率对比

| 平台 | 估价方式 | 准确率争议 | 特点 |
|------|------|:---:|------|
| 爱回收 | AI+38项质检 | 高 | 需专业设备 |
| 闲鱼回收 | 照片+人工 | 中 | 偏差大 |
| 转转 | AI验机+邮寄 | 中高 | 只做3C |
| 再生博士 | AI+行业DB | 高 | 废料品类 |

## 实施建议

### 三阶段落地

| 阶段 | 做什么 | 技术依赖 | 时间 |
|------|------|------|:---:|
| **MVP** | 腾讯云API识别 + 手动估价表 | 腾讯云TIIA + 本地价格表 | 2-4周 |
| **V1** | 百度AI补充 + 基础估价模型 | API + Python定价脚本 | 4-8周 |
| **V2** | Qwen3-VL微调 + 动态定价 | GPU + 训练数据 | 3-6月 |

### 成本估算（MVP阶段） — **选定百度AI**

| 项目 | 方案 | 月成本 |
|------|------|------|
| 物品识别 | 百度AI 通用物体识别（10万类） | **¥0**（企业认证 3万次/年免费） |
| 补充识别 | 腾讯云 TIIA 商品识别 | ¥0-22.5（1000次/月免费 → 超出 2.5元/千次） |
| 云服务器 | 微信云托管 / 轻量服务器 | ¥100-300 |
| **合计** | | **¥100-300/月（几乎全免）** |

### 为什么选百度AI

| 维度 | 百度AI |
|------|------|
| 免费额度 | 个人 1 万次/年，企业 3 万次/年 |
| 品类覆盖 | 10 万种物体/场景，覆盖面最广 |
| 冷启动 | 前几个月完全零成本 |
| 腾讯云后备 | 免费额度不够后切换，单价 2.5 元/千次，微信生态集成方便 | |

### 关键风险

| 风险 | 应对 |
|------|------|
| API识别覆盖率不足（特殊品牌/老旧型号） | 人工标注补充 + 用户反馈机制 |
| 估价准确率低导致用户不信任 | 初期采用"估价范围"而非精确值 + 人工复核 |
| 二手价格数据获取困难 | 先用大宗商品价格+折旧公式，逐步积累自有数据 |
| 政策变化（废旧家电估价标准） | 关注政策动态，预留调参空间 |
